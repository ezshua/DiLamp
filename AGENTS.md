# AGENTS.md — инструкции для агента

> Проект: **DiLamp**, умная лампа с адресуемой подсветкой WS2812.
> Источник истины по архитектуре и решениям — [`docs/PLAN.md`](docs/PLAN.md). При конфликте с этим файлом побеждает план.
> Список задач с критериями приёмки — [`docs/TODO.md`](docs/TODO.md).

## 1. Что это

Прошивка для Arduino Nano (ATmega328P), управляющей двумя вложенными кольцами адресуемых светодиодов WS2812 (12 + 8 = 20 шт.). Лампа автономна: управление тремя кнопками на корпусе. Питание — от USB или от встроенного аккумулятора (Li-ion + TP4056 + MT3608 → 5 В). Диагностика и консоль — через последовательный порт 115200 бод.

## 2. Стек

| Слой | Технология |
|---|---|
| Язык | C++17, без динамической памяти |
| Платформа | AVR, ATmega328P, 16 МГц, 30 КБ flash / 2 КБ SRAM |
| Сборка | PlatformIO Core 6.1.19, платформа `atmelavr` |
| IDE | VS Code + PlatformIO IDE Extension |
| LED-библиотека | Adafruit_NeoPixel 1.12 |
| Тесты | Unity, нативное окружение `env:native` |
| Хранение состояния | avr-libc EEPROM |
| Документация | Русский язык, идентификаторы кода — английский |

Конфигурации сборки: `nano` (основная), `lgt` (LGT8F328P, заготовка, не проверяется), `native` (тесты без железа).

## 3. Жёсткие правила

Нарушение любого пункта — повод остановиться и спросить, а не обойти правило молча.

### 3.1. Память и частота

- **FastLED запрещён.** На ATmega328P с 2 КБ SRAM она не помещается. Только Adafruit_NeoPixel.
- **`F_CPU` обязан оставаться в диапазоне 15,4–19 МГц.** Adafruit_NeoPixel поддерживает лишь 7,4–9,5 / 11,1–14,3 / 15,4–19 МГц; всё остальное даёт `#error "CPU SPEED NOT SUPPORTED"`. Никогда не поднимать частоту ради производительности.
- **Никакого `String`.** Только `const char*`, строки — в `PROGMEM` и `F("...")`.
- **Никаких `malloc`/`new`.** Статические массивы фиксированного размера.
- Следить за отчётом `pio run -t size`. Порог: **< 60 % flash, < 50 % SRAM**. Стоимость логирования и консоли — ориентир 400–600 Б flash и ~200 Б SRAM.

### 3.2. Тайминги и блокировки

- **`show()` вызывать только при изменении кадра** (dirty-флаг). Без этого метроном `millis()` теряет тики на каждом кадре.
- **Запрещены `delay()` и любые блокирующие вызовы.** Всё — конечные автоматы по времени.
- **Прямой `Serial.print*()` в прикладном коде запрещён.** Буфер Serial — 64 байта, при 115200 бод переполнение блокирует цикл. Только через `Logger`.
- Парсер команд — **побайтовый, неблокирующий**. Никаких `readStringUntil()`.
- Кнопки опрашиваются **состоянием в главном цикле**, не на прерывании: `show()` глушит прерывания на ~600 мкс.

### 3.3. Портируемость

- **`config.h` не зависит от `Arduino.h`** — только `<stdint.h>`. Иначе нативные тесты не соберутся.
- **Никаких `#ifdef` по плате в бизнес-коде.** Различия плат живут только в `platformio.ini` и в одном `DILAMP_ADC_BITS`.
- `BatteryMonitor` нормализует `analogRead()` к 10-битному диапазону: LGT8F328P даёт 12 бит.

### 3.4. Аппаратные ограничения

- **Яркость ограничена сверху.** `kMaxBrightness = 180`, `kPerPixelMax = 160`. Не повышать без пересчёта тока: 20 диодов на полном белом дают 1,2 А, а MT3608 надёжно выдаёт ~1 А.
- **Лента питается мимо стабилизатора Nano** — по рельке `+5V_LAMP`, а не через вывод 5V платы как источник.
- Пины кнопок **не зашивать в код эффектов**: под энкодер D2/D3/D4 придётся освободить. Весь ввод только через интерфейс `Controls`.

### 3.5. Хранение и публикация

- **Агент никогда не выполняет `git push`.** Коммиты локальные, публикует владелец.
- Репозиторий публичный: никаких токенов, ключей и учётных данных в коде и в истории.
- Подробности — §4.11 плана.

## 5. Архитектурная карта

```
main.cpp                 конечный автомат: опрос ввода → логи → эффект → show()
  │
  ├── Controls (интерфейс)── Buttons3 (сейчас) · EncoderKnob (задел, выключен)
  ├── Logger   ──────────── кольцевой буфер, неблокирующий сброс в Serial
  ├── CommandConsole ────── побайтовый парсер, таблица команд
  ├── SettingsStore ─────── версионированная запись + CRC в EEPROM
  ├── BatteryMonitor ────── делитель 200к/100к на A0, нормализация по DILAMP_ADC_BITS
  ├── LedBus   ──────────── обёртка над NeoPixel + dirty-флаг
  ├── RingLayout ────────── маппинг «кольцо + индекс» → индекс ленты
  └── Effects  ──────────── EffectContext { nowMs, layout, bus, brightness }
        └── 6 эффектов в src/effects/
```

Правило слоёв: `Effects` ничего не знают о кнопках, Serial и EEPROM. `Color` и `RingLayout` — чистые функции без побочных эффектов, поэтому и тестируются нативно.

## 6. Команды

В VS Code — через плагин PlatformIO: панель **PROJECT TASKS** (Build / Upload / Monitor) и **TESTING** для нативных тестов. Выбор окружения — в статус-баре.

Эквивалент в терминале:

```bash
pio run -e nano                 # сборка основной прошивки
pio run -e nano -t upload       # прошивка
pio device monitor -b 115200   # монитор
pio test -e native              # нативные тесты, без железа
pio run -e nano -t size         # отчёт по памяти
```

## 7. Порядок работы

1. Открыть `docs/TODO.md`, взять **первую** неотмеченную задачу.
2. Выполнить её, отметить `[x]`, зафиксировать критерий приёмки.
3. Запустить `pio test -e native` и `pio run -e nano -t size`.
4. Сделать локальный коммит в `main`. **Не пушить.**
5. Вернуться к п. 1.

Не брать задачи «на будущее» вперёд текущей: этапы выстроены так, что каждый следующий опирается на проверенный предыдущий.

## 8. Критерии готовности задачи

Задача считается выполненной, если одновременно:

- `pio test -e native` — все тесты зелёные;
- `pio run -e nano` — собирается, память в пределах порогов §3.1;
- новое поведение покрыто тестом, а не «посмотрел глазами»;
- чекбокс в `docs/TODO.md` отмечен, критерий приёмки выполнен;
- локальный коммит сделан;
- ни одно правило §3 не нарушено — если пришлось нарушить, это обсуждается с владельцем явно.

## 9. Чего в проекте нет намеренно

Микрофон, таймер/будильник, Wi-Fi/Bluetooth, ESP, прошивка корпуса и механика, аппаратная проверка LGT8F328P. Не добавлять это без запроса — план §10 фиксирует границу MVP.

# STEP_PROMPT — промпт для агента, выполняющего один шаг

> Назначение: воспроизводимая процедура выполнения **одной** задачи из [`TODO.md`](TODO.md) агентом, который начинает сессию с чистого листа.
> Владелец проекта правит файлы вручную в VS Code между шагами, поэтому промпт строится вокруг сверки фактического состояния, а не доверия тексту плана.

## Как использовать

Новый агент, одна сессия — одна задача:

```
Работай в репозитории DiLamp. Выполни ровно один шаг по процедуре
из docs/STEP_PROMPT.md, раздел «ПРОМПТ».
```

Текст ниже копируется в агента дословно, вместе со ссылкой на этот файл.

## Что здесь универсально, а что правится под проект

| Часть | Переносимость |
|---|---|
| Протокол: шаги 0–6, таблица расхождений, запреты, формат отчёта | **Универсально.** Работает в любом репозитории, где владелец правит файлы между сессиями |
| Имя репозитория, пути к `TODO.md` и `AGENTS.md` | Правится под проект |
| Команды `pio run -e nano`, `pio run -e lgt` | Правится под проект — у другой платформы свои |
| Ссылки на жёсткие правила `AGENTS.md` §3 | Правится под проект |

При смене платформы, репозитория или системы сборки правятся нижние строки промпта. Протокол остаётся без изменений.

---

# ПРОМПТ

*(начать копирование отсюда)*

---

```text
Ты работаешь в репозитории DiLamp над прошивкой умной лампы.
Задача сессии: выполнить РОВНО ОДИН шаг из docs/TODO.md и остановиться.

═══════════════════════════════════════════════════════
ГЛАВНЫЙ ПРИНЦИП: ПЛАН — ГИПОТЕЗА, РАБОЧЕЕ ДЕРЕВО — ФАКТ
═══════════════════════════════════════════════════════

Владелец проекта правит файлы вручную в VS Code между шагами.
Текст задачи в TODO.md может расходиться с реальностью: он устаревает,
а чекбокс владелец отмечать не обязан.

Никогда не начинай работу с веры в текст задачи. Сначала установи
фактическое состояние — потом решай, что делать.

═══════════════════════════════════════════════════════
ШАГ 0. УСТАНОВИТЬ ФАКТИЧЕСКОЕ СОСТОЯНИЕ  (обязательно)
═══════════════════════════════════════════════════════

  git status
  git log --oneline -10
  прочитать docs/TODO.md          — найти первую неотмеченную задачу
  прочитать целевые файлы задачи   — целиком, а не по памяти

═══════════════════════════════════════════════════════
ШАГ 1. СВЕРИТЬ ПЛАН С РЕАЛЬНОСТЬЮ
═══════════════════════════════════════════════════════

Сравни три источника: текст задачи · состояние на диске · история git.

  Задача уже выполнена, чекбокс не отмечен
      → НЕ переделывать. Проверить доказательствами (сборка проходит,
        сборка проходит, файлы на месте), отметить чекбокс, отчитаться.

  Задача выполнена частично
      → Описать, что уже есть. Спросить, продолжать ли.

  Владелец сделал задачу иначе
      → Прочитать его версию, понять замысел.
        НЕ «восстанавливать» версию из плана — она устарела.

  Расхождение документации с кодом
      → Править документ под код, а не код под документ.

Если задача №N требует результата задачи №N-1, а №N-1 не выполнена —
остановиться и спросить, а не чинить это молча.

═══════════════════════════════════════════════════════
ШАГ 2. УЧИТЫ ЧУЖИЕ ИЗМЕНЕНИЯ
═══════════════════════════════════════════════════════

Файлы в `git status`, которых ты не менял, — это правки владельца.

  • Если они в зоне текущей задачи — учти их и спроси, не конфликтуют
    ли они с задачей.
  • Никогда не выполнять: git checkout · git restore · git reset ·
    git stash · git clean.
  • Никогда не перезаписывать файл, не прочитав актуальное содержимое.
  • Если не понимаешь, зачем владелец что-то менял, — спроси, а не
    «поправь».

═══════════════════════════════════════════════════════
ШАГ 3. ВЫПОЛНИТЬ
═══════════════════════════════════════════════════════

  • Ровно одну задачу. Не больше.
  • Никаких попутных рефакторингов, «улучшений», расширения scope.
  • Соблюдать жёсткие правила AGENTS.md §3 (память, F_CPU, блокировки,
    питание, портируемость).
  • Инструменты — через уже установленное расширение VS Code.
    Дубликаты не создавать. Если чего-то не хватает — ПРЕДЛОЖИ
    установить, не устанавливая молча.

═══════════════════════════════════════════════════════
ШАГ 4. ПРОВЕРИТЬ РЕЗУЛЬТАТ
═══════════════════════════════════════════════════════

  pio run -e nano            → основная плата собирается
  pio run -e lgt             → вторая плата собирается
  pio run -e nano -t size    → память в пределах порогов
  критерий приёмки задачи     → выполнен
  правила AGENTS.md §3        → ни одно не нарушено

Если проверка не проходит — не чини чужой код, чтобы «заставить сборку
пройти». Опиши расхождение.

═══════════════════════════════════════════════════════
ШАГ 5. ОТМЕТИТЬ И ОСТАНОВИТЬСЯ
═══════════════════════════════════════════════════════

  • Отметить [x] в docs/TODO.md
  • НЕ выполнять git commit
  • НЕ выполнять git push
  • НЕ переходить к следующей задаче

═══════════════════════════════════════════════════════
ШАГ 6. ОТЧЁТ  (ровно в этом виде)
═══════════════════════════════════════════════════════

  1. Задача
     Номер и название.

  2. Расхождения с планом
     Что обнаружено при сверке. Если расхождений не было — так и напиши.

  3. Сделано
     Файлы и суть изменений.

  4. Проверки
     Точные цифры: сборка под обе платы, flash и SRAM в байтах и процентах.

  5. За владельцем
     Коммит, ручные проверки железа, решения, которые должен принять человек.

  6. Открытые вопросы
     Что требует решения владельца. Если вопросов нет — «нет».

═══════════════════════════════════════════════════════
ЖЁСТКИЕ ЗАПРЕТЫ
═══════════════════════════════════════════════════════

  ✗ git commit / git push
  ✗ откат чужих изменений
  ✗ доверие плану без проверки фактов
  ✗ больше одной задачи за сессию
  ✗ молчаливая установка инструментов
  ✗ изменение архитектуры без согласования

  ✓ Остановиться и спросить

Неверно начатая задача обходится дороже, чем лишний вопрос.
```

## Почему протокол такой

| Решение | Причина |
|---|---|
| Шаг 0 обязателен и идёт **первым** | Иначе агент прочитает «не отмечено» и начнёт переделывать уже сделанное |
| Три независимых источника сверки | Один чекбокс нельзя считать правдой — он живёт в отдельном файле и стареет |
| Отдельный случай «выполнена, но не отмечена» | Самая частая ситуация при работе, где владелец правит код между сессиями; без этого правила агент дублирует работу |
| Запрет `checkout` / `restore` / `stash` | Молчаливый откат уничтожит ручную правку, и владелец этого не заметит |
| «Править документ под код, а не наоборот» | Код проверяется компилятором под обе платы, документ — ничем. Код истина |
| Числа в отчёте, а не «всё хорошо» | Владелец ревьюит в VS Code и должен видеть факт, а не пересказ |
| Стоп-условие «задача N−1 не сделана» | Этапы выстроены с зависимостями; чинить их молча — верный способ получить неверную прошивку |
